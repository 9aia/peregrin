# Design principles

1. **Declarative.** A document describes _what_ values it contains, not _how_ to compute them. Computation is expressed through field declarations, not imperative code.
2. **Schema-first.** Every field has a schema. Validation is not optional — it is part of the language semantics.
3. **Named functions are emergent.** The language defines no built-in functions and no `functions:` keyword. A function is just an object with a `body` field stored in a field. The `apply` host primitive evaluates function bodies with bound arguments. User-defined functions compose from host primitives and each other — no new language constructs needed.
4. **Composition over keywords.** The language has a small set of primitives. Complex patterns (imports, config spreading, conditional loading) emerge from composition, not from dedicated syntax.
5. **Format-agnostic.** Documents can be written in YAML, JSON, TOML, or any format that maps to JSON-compatible values.
6. **Embeddable.** The core is a small kernel designed to be embedded in a host application, not a standalone language ecosystem. The AST has zero dependencies. The VM is generic over a `Host` trait — the host provides all functions, the VM evaluates expressions and returns values. This is the Lua/Rhai embedding model, not the Python/Unison model. No runtime owns the codebase, no toolchain must be shipped, no garbage collector is imposed on the host.
7. **Host provides the world.** The language defines no built-in functions, no standard library, no I/O primitives. Everything the evaluator can do is provided by the host via the `Host` trait. The host decides which functions exist, which namespaces are available, and what side effects are permitted. The language is a pure evaluation kernel; all policy lives in the host.
8. **Content addressing is optional.** Definitions can be identified by hash (SHA-256 of canonical JSON) for deduplication, reproducible builds, and cross-machine sharing. But content addressing is a storage layer, not a language-level constraint. Documents evaluate correctly without ever touching a `DefinitionStore`. The language does not require a codebase database, hash-based imports, or a package manager to function.
9. **Control flow is emergent, not built-in.** The language defines no conditional, loop, pattern-matching, or let-binding syntax. These emerge from host functions operating on first-class function values: `if(cond, then_fn, else_fn)` evaluates the matching branch via `apply`, `map(items, fn)` iterates in the host, `match(value, cases)` dispatches by structure. Let-bindings are just function parameters — `apply(fn(x) { ... }, value)` binds `x` to `value`. The language provides the evaluation kernel (literals, path lookups, function calls, handlers); the host provides the control flow. This keeps the syntax small while allowing a host that provides `if`, `map`, `match`, `filter`, `reduce` to reach arbitrary computational expressiveness — the scope boundary is in what the _language_ bakes in, not in what a _host_ can provide.
