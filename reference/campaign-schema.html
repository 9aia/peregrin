Campaign schema ​

The full YAML → Campaign contract, ported from v1 model.ts. The typed model lives in peregrin-core (Campaign::from_dict, Node::from_dict); expansion passes (include, snippet, discovery) run first in peregrin-loader-yaml. from_dict is total for nodes — bad scalars coerce or drop — but nodes:/events: that aren't arrays are a hard error.

EventSchema ​

{type, fields, schema, annotations} — used by events:, node input:/output:, and driver contracts.

  • fields shorthand: name: <json-type>[?] where ? marks optional; unknown type names compile to string.
  • schema is a full JSON-schema dict and wins over fields when non-empty.
  • Compiled schema checks required properties and per-property primitive type (string/integer/number/boolean/array/ object/null); non-object payloads fail (root).

Load-time normalization ​

Applied by Node::from_dict / the loader expansion, in order:

  1. Discovery — .peregrin/ then .handl/ then the base dir (recursive, dot-dirs skipped; the named roots win name dedupes in scan order — .peregrin is the rebrand name, .handl stays for v1 compatibility): *.node.yml, *.snippet.yml, *.event.json, *.config.yml, *.fn.yml fold into nodes, snippets, payload_schemas, config, functions. *.handler.py, *.secret.yml, .env are discovered for other consumers.
  2. include: — a dict-level key deep-merges file contents under local keys; the top-level include: list does the same per path. ${include(path)} inside strings splices the parsed value (typed when it's the whole string). Circular includes error by path.
  3. snippets: — snippet: <parent> inheritance inside the table resolves to a fixpoint (local wins); snippet: <name> in any dict merges the body under local keys; ${snippet(name)} interpolates like ${include()}. Cycles and non-dict bodies error.
  4. Deep merge — dicts merge per-key local-wins, arrays concatenate local-first, scalars take local.
  5. with: rejection — any node with: key is a hard load error (renamed params, ADR-0025).
  6. Poll normalization — a truthy poll: appends <id>.tick to on and emits, merges poll.until into until, and backfills params.interval from poll.interval.
  7. Schedule normalization — driver: schedule appends <id>.fire to on and <id>.fire + <id>.scheduled to emits (the poll: <id>.tick convention, ADR-0018) and defaults max_fires: unlimited. Each landed <id>.fire re-invokes the driver to arm the next cron occurrence.
  8. Self-trigger default — driver: cli/polling with params.mode != "interval" defaults max_fires: 100 (others: 1; schedule: unlimited).

Coercion quirks kept from v1: scalar strings in list positions iterate into characters (on: start → ["s","t","a","r","t"]) — always write lists; strict, requires_capability, deterministic parse JS-truthy.

Capability merge ​

capabilities merges {...workflow, ...node} for the template ctx and via CapabilityChecker.merge for driver-param checks: node keys override; dict-list keys (shell, http, python, webhook) merge their allow/deny/ports/hosts/paths lists; top-level list keys (secrets, agents, urls) replace — or union when the node sets merge: true. default_policy defaults to deny under strict, allow otherwise.
